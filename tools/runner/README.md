# Прогонник

Сценарії для Node без графічних бібліотек. Перший робить N прогонів Lighthouse
за адресою, пише всі значення в CSV і будує HTML-діаграму розкиду. Другий
вимірює взаємодію з елементом сторінки (довгі завдання, затримка взаємодії,
функції, на які припав час). Прогонник міряє адресу, тому працює з будь-яким
застосунком без правок коду.

## Як запустити

```
npm ci
npm run lighthouse -- http://localhost:3102/ --runs 10 --variant "запит на сервері"
npm run html -- ../../measurements/lighthouse.csv --highlight 2,7
npm run interaction -- http://localhost:3102/ --field "Фільтр" --repeat 5 --cpu 4
npm run check
```

Потрібні Node не нижче за `engines` пакета Lighthouse (`>=22.19`) і встановлений
Chrome. Нестандартний шлях до Chrome задається змінною `CHROME_PATH`
(README chrome-launcher 1.2.1).

| Команда | Параметри | Що пише |
|---|---|---|
| `lighthouse -- АДРЕСА` | `--runs` (10), `--variant`, `--device mobile` або `desktop` (mobile), `--throttling devtools`, `simulate` або `provided` (devtools), `--csv` (`measurements/lighthouse.csv` у корені проєкту), `--highlight 2,7`, `--component` (ЛР3) | рядок CSV на прогін на кожну величину (LCP, FCP, TTFB, TBT, CLS, байти JS), а на адресі Vercel ще й заголовки документа `x-vercel-cache` і `x-vercel-id` з одиницею `—`, `scatter.html` поруч із CSV, елемент LCP у виводі |
| `html -- ФАЙЛ.csv` | `--highlight`, `--out` | лише діаграму з наявного CSV |
| `interaction -- АДРЕСА` | дія `--field "НАЗВА"` (з `--text`, 97), `--click "НАЗВА"` (з `--role`, button, і `--times`) або `--press КЛАВІША --on ІМ'Я` (з `--role`, combobox, і `--times`); також `--measure НАЗВА`, `--repeat` (3), `--cpu` (1), `--variant`, `--csv` (`measurements/interaction.csv`), `--component` (ЛР3), `--mode production` або `development` | на кожен повтор кількість довгих завдань, найдовше завдання, найбільша затримка взаємодії, тривалість позначки `performance.measure` з `--measure`, п'ять функцій з найбільшим власним часом |

Елемент для дії шукається за роллю й доступним іменем, тими самими, що в
контракті компонента. Якщо такого елемента немає, команда завершується
повідомленням про це.

## Що має бути видно

1. Розкид ненульовий. Десять прогонів тієї самої адреси на тій самій машині
   дають десять різних LCP і TTFB. Діаграма показує кожен прогін точкою,
   медіану рискою, мінімум і максимум «вусами».
2. Тротлінг за замовчуванням `devtools`. Lighthouse за замовчуванням
   використовує `simulate`, яку документація описує як «very fast and
   deterministic» (`docs/throttling.md`, v13.4.1). З `devtools` числа описують
   те саме завантаження, що видно в панелях Performance і Network. Для
   порівняння доступний `--throttling simulate`.
3. Елемент LCP називається явно і групується за селектором, бо число LCP
   залежить від того, який елемент переміг.

## Обмеження

1. Прогони йдуть по одному, бо документація Lighthouse забороняє збирати
   кілька звітів одночасно на одній машині (`docs/variability.md`, v13.4.1).
2. Режим navigation не вимірює INP, аудит `interaction-to-next-paint` у
   Lighthouse 13.4.1 підтримує лише режим timespan. Затримку взаємодії дає
   `interaction` за Event Timing.
3. `@lhci/cli` 0.15.1 містить Lighthouse 12.6.1, тому числа прогонника і
   конвеєра ЛР4 отримано різними версіями.
4. У поле вводяться цифри, бо для символів поза розкладкою US Puppeteer
   надсилає лише подію `input`, і Event Timing взаємодії не бачить.
5. Трансляція екрана забирає процесор, тому серія під час заняття пишеться в
   окремий CSV (`--csv`).

## Що перевіряють тести

| Набір | Що перевіряє |
|---|---|
| `scatter` | CSV іншого формату відхиляється, серія відповідає одній команді, десять прогонів дають десять точок на смузі з медіаною, мінімумом і максимумом, умови в заголовку сторінки, два виділені прогони дають таблицю різниці, сторінка без зовнішніх сценаріїв і стилів |
| `live` | на локальній сторінці в Chrome два прогони Lighthouse дають по рядку на прогін на кожну величину і `scatter.html`, `interaction` знаходить довге завдання на кожне введення, натискання і клавішу з важким обробником і жодного без нього, відсутній елемент дає зрозуміле повідомлення |
