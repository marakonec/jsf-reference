# Еталонний проєкт після ЛР2

Стан еталонного проєкту дисципліни «JavaScript Frameworks» після другої
лабораторної роботи. До стану після ЛР1 додано два робочі простори на
Next.js. `variant-client/` є варіантом «запит на клієнті», у якому дані
клієнтські компоненти беруть з обробників маршрутів. `variant-server/` є
варіантом «запит на сервері», у якому дані читають серверні компоненти, а
каталог кешується на сервері. Документи ЛР2 заповнено (`JOURNAL.md`,
розділ 2, і `ADR-002.md` з розділами «Мапа стану» і «Рішення щодо маршрутів»).

## Команди

| Команда | Що робить |
|---|---|
| `npm ci` | встановлення залежностей за файлом блокування |
| `npm run check` | середовище, типи, лінтинг, складання, тести |
| `npm run ready -- 2` | повнота документів ЛР1 і ЛР2 |
| `npm run start --workspace variant-server` | зібраний варіант «запит на сервері» на порту 3102 (`variant-client` на порту 3101) |
| `npm run route -- variant-server /` | обсяг JavaScript маршруту зібраного варіанта |
| `npm run find -- variant-server SECRET_MARKER` | у яких файлах складання трапляється рядок ключа постачальника |

## Змінні оточення варіантів

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `SOURCE_DELAY_MS` | 300 | затримка джерела даних у мілісекундах, імітує віддалене API |
| `CACHE_DISABLED` | не задано | значення `1` вимикає кеш каталогу на сервері для вимірювання «без кешу» |

Затримка джерела діє і на розгорнутій адресі, якщо змінну не задано в
налаштуваннях хостингу. Її значення є умовою вимірювання і записується в
журнал.

## Розгортання

Кожен варіант розгортається окремим проєктом Vercel з Root Directory
`variant-client` або `variant-server`. Варіанти беруть дані з `data/data.json`,
а тип запису, фільтр і агрегат з `shared/data.ts` кореня репозиторію. Vercel
бачить ці файли, бо параметр Include source files outside of the Root Directory
in the Build Step у нових проєктах увімкнено за замовчуванням
(https://vercel.com/docs/monorepos/monorepo-faq, 26.10.2026).
